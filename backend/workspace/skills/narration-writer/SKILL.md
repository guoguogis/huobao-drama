# 口播稿写作规范

## 为什么字数必须精确

成片的画面长度**不是随便定的**：画面要跟着音轨走。音轨由 TTS 合成，语速由项目设置固定
（默认 **1.1 倍**），因此「这段话说多久」是可算的：

```
朗读时长(秒) = 口播字数 ÷ (4.2 字/秒 × 语速倍率)
```

1.1 倍速下 ≈ **4.62 字/秒**，也就是 60 秒成片 ≈ **277 字**。
写超了 → 镜头被迫加速或截断；写少了 → 画面要冻结尾帧拖时间。
所以写作前必须先拿 `read_narration_brief` 返回的 `char_budget`，写完自查字数。

## 三个版本怎么差异化

三个版本要让用户一眼看出「这是三个不同的片子」，而不是三段同义改写。常用的三组角度：

| 角度 | 开头钩子 | 适合主题 |
|---|---|---|
| 悬念提问式 | 抛出反常识问题／先给结论再解释「为什么」 | 科普、认知纠偏 |
| 数据冲击式 | 一个具体数字或对比，先砸出反差 | 商业、行业分析、财经 |
| 故事场景式 | 一个具体的人/时间/地点切入，带情节 | 人物、历史、情感、文化 |

差异化要求：
- 开头 3 秒的钩子类型不同
- 中段的组织方式不同（时间线 / 因果链 / 对比并列）
- 结尾落点不同（观点收束 / 行动建议 / 余味反问）

## 写作硬约束

1. **一句一行**：句子边界 = 后续镜头边界。不要在一个自然段里塞五句话。
2. **单句 12~28 字**：短句利于切镜与配音；超过 30 字的长句会被拆成两镜，节奏变碎。
3. **口语可念**：写完默读一遍，出现书面语（「综上所述」「旨在」）就改掉。
4. **数字口语化**：「30%」写「三成」，「1200 万」写「一千两百万」。
5. **不写制作说明**：不写镜头、画面、BGM、字幕、停顿标记。
6. **不加 markdown**：不要小标题、编号、加粗、列表符号——这些会被念出来或被 TTS 读错。
7. **字数落点**：`char_budget` 的 ±8% 以内；三版之间字数可以有小差异，但都要在区间内。

## 需要停顿与重音时怎么办

TTS 只认标点：
- 句子结束用「。」→ 自然收尾停顿
- 句中短停用「，」→ 约 0.2~0.3 秒
- 需要更明显的停顿就把长句拆成两句（同时也就多了一个镜头）
- **不要**写「（停顿两秒）」「**重点**」这类标记，它们会被读出来

## 交付

调用 `save_narration_scripts` 保存三个版本，每个版本带 `angle`（角度名）和 `title`（短标题），
正文放在 `content`。保存后界面会展示三版供人工选定；**选定之前不要继续做分镜**。
