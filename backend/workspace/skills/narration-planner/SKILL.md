# 口播分镜与音画同步规范

## 同步的因果链（必须先理解）

```
口播稿（一句一行）
   → 代码按句切分 → 每句一镜（shot_plan，含每镜时长）
   → 每句单独 TTS（1.1 倍速）→ 实测每句音频时长
   → 每个镜头的画面被重定时到「该句音频时长」
   → 片段按顺序拼接 → 画面与声音天然对齐
```

所以：**镜头的边界由句子决定，镜头的时长由这句话念多久决定**。
你（模型）不需要也不应该自己去估时长——`read_selected_narration` 已经把 shot_plan 算好了。

## 关键帧提示词规范

每个镜头只写**一张起始画面**的提示词（末帧由下一镜头的起始画面提供，这就是"首尾帧视频"的用法）。

单个提示词的构成（单段连贯描述，不要分点）：

1. **主体与动作**：画面里是谁/什么，正在做什么（具体到肢体与朝向）
2. **景别与构图**：远景/中景/近景/特写；主体在画面中的位置（三分法、居中、前景遮挡）
3. **环境与时间**：地点、时段、天气、背景元素
4. **光线与色调**：光源方向、冷暖、对比度
5. **材质与风格**：纸张/拼贴/颗粒/半色调等风格关键词（由项目风格预设统一，不要自创风格词）

禁止：
- 「镜头 1」「画面中」「这一帧」等元话语
- 画面内的大段文字（需要文字时只允许少量准确汉字）
- 与相邻镜头完全相同的描述（否则首尾帧动画没有变化）

## 相邻镜头的连续性（首尾帧的命门）

首尾帧视频要求「从 A 图演到 B 图」，因此相邻两镜必须能接上：

- **视觉锚点**：同一主体、同一空间、同一色调至少保持一项连续
- **变化可控**：两帧之间是"同一场景内的推进"（走近、转头、展开、滑入），不是跳到另一个场景
- **不要瞬移**：避免全景切到无关的特写
- 若必须换场景，就在 `video_prompt` 里写成明确的过渡（推移、遮挡转场、拉远）

## 音频（配音）提示词规范

`narration_text` 就是 TTS 的输入，规范只有三条：

1. **与 shot_plan 的句子完全一致**：不要改写、不要增删字；改字就会改时长，画面就错位
2. **标点即节奏**：「。」句末停顿、「，」句中短停；需要长停顿就拆句（拆句=多一镜）
3. **不写任何提示语**：不写「（停顿）」「（重音）」「语速 1.1」，语速由项目设置统一控制

## `video_prompt`（首尾帧之间的运动）怎么写

按 3 秒一段、每段一行，描述**从本镜头画面到下一镜头画面**的发生过程：

- 先说运动主体与方式（推进、拉远、平移、展开、组装、翻页）
- 再说各元素的先后与因果（先亮灯再出现人物，而不是同时冒出来）
- 明确尾态：最后要落到下一镜头的构图
- 不写总秒数（时长由 clip 生成参数决定），用「前段/中段/收束」这类相对节拍

## 交付

调用 `save_narration_shots` 一次性保存全部镜头（`shot_number` 连续递增）：
每个镜头带 `keyframe_prompt`、`narration_text`、`video_prompt`、`atmosphere`、`duration_sec`（取 shot_plan 的值）。
保存后界面会允许逐镜生成图片，再把相邻两帧指定为首尾帧生成视频片段。
