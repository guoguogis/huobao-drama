# 「设计即代码」科普视频 · 总览与制作说明

> 交付形态：2 分 30 秒横屏科普片（16:9，1920×1080），手绘白板/粉笔风，纯中立科普、不出现任何品牌名。
> 制作顺序：**先生图 → 再合成视频**。本文件是流程说明书，正文文案见 01～05。

---

## 一、这套文件怎么用

| 文件 | 用途 | 谁用 |
|---|---|---|
| `00-总览与制作说明.md` | 流程 SOP、风格 bible、参数建议 | 你自己 / 制作同学 |
| `01-口播配音稿.md` | 27 段口播，按镜号+时间码，可直接丢给 TTS | 配音环节 |
| `02-分镜与生图提示词.csv` | 27 条英文提示词 + 1 条风格锚点（S00），含负向词与屏幕文字，批量生图用 | 生图环节 |
| `03-字幕.srt` | 与口播逐句对齐的字幕，可直接导入剪辑软件 | 剪辑环节 |
| `04-发布文案包.md` | 标题 / 封面字 / 简介 / 标签 / 置顶评论 | 发布环节 |
| `05-事实依据与来源.md` | 每条关键论点的出处，便于自查与反驳 | 你自己 |
| `build-shotlist.py` | 分镜表的**唯一事实来源**（改提示词/板书改这里，重跑生成 02 与 27 个提示词文件） | 维护用 |
| `check-sync.py` | 校验「口播稿 ↔ 字幕 ↔ 分镜表」逐句一致，并检查每镜字数是否超时长预算 | 改稿后必跑 |
| `make-contact-sheet.py` | 把 27 张图拼成联系表，用于统一性复查 | 出图后必跑 |

**校验基准**：全片 27 个分镜（另有 1 张风格锚点图 S00）、总时长 150 秒（2:30）；口播正文 **472 个汉字**（不含英文术语），平均 **3.15 字/秒**——开发者视角版刻意留出了比信息版更多的停顿余量，因此录音时**不要加速**。改完稿请跑 `check-sync.py`，应输出 `RESULT=PASS`。

## 二、成片结构（章节与时间轴）

| 时间 | 章节 | 镜号 | 作用 | 情绪目标 |
|---|---|---|---|---|
| 00:00–00:10 | 开场：那道断层 | S01–S02 | 直接用开发的日常抓人，不下结论 | 疲惫、熟悉、苦笑 |
| 00:10–00:31.5 | 一、它想干掉的是手工活 | S03–S06 | 给定义 + 划清它省掉的是什么 | 微微提亮 |
| 00:31.5–01:25 | 二、它凭什么读得懂设计稿 | S07–S15 | 讲原理与 6 个工程难题（**最有"这人懂我"感的一段**） | **故意冷静**，提供可信度 |
| 01:25–01:46 | 三、它到底替你省了什么 | S16–S19 | 四条价值，逐条对应原文论点 | **全片最高点**，被说中 |
| 01:46–02:14.5 | 四、但别指望它替你上线 | S20–S24 | 转折与边界，中立立场的核心 | 沉下来，诚实 |
| 02:14.5–02:30 | 五、那你的活，会变成什么样 | S25–S27 | 回答"我会不会被替代" | 温和的笃定，不煽动 |

> **口播稿为「开发者视角版」**（`01-口播配音稿.md`）：全片的"你"= 开发工程师，设计师是"对面"而非对手；痛点全部换成开发每天真过的那些（照稿再实现一遍、一堆没语义的 div、被说"跟设计稿不太像"、组件库对不上、硬编码颜色、最后一公里还是自己补）；词汇升级到开发听得懂的层级（绝对定位 / 中间表示 / 组件 / 接口 / 代码仓库）；并主动接住"我会不会被替代"——答案是拆的是工序，不是人。
> **两条硬约束**：① **绝不拉踩设计师**，所有痛点归给流程、不归给人；② **事实不能编**，全片没有虚构的百分比、工时、人数数据。

> 章节标题卡（一、二、三…）建议做成**后期叠加层**，不要写进生图提示词——见下方"为什么画面里不要有字"。

## 三、风格 bible（生图统一性的唯一来源）

### 1. 视觉定义

- **主视觉**：白板马克笔手绘。米白纸面 + 黑色不匀线稿 + 少量平涂/斜线排线阴影。
- **章节页**：深墨绿黑板 + 白色粉笔质感（只用于 5 张章节卡，情绪切换用）。
- **色板**：底色 `#F7F5F0`｜线稿 `#1F2328`｜强调蓝 `#2F6BFF`｜强调橙 `#FF7A45`｜辅助灰 `#8A9099`。全片**只用这 5 个颜色**，这是统一感的关键。
- **线条**：粗细不匀、略带手抖，允许溢出与重描；不用完美直线、不用羽化。
- **线条连续性（硬性要求，已实测踩坑两次）**：所有线条必须**连续、不中断**，且**一律实线**——笔尖与它画出的线必须相接，线框必须闭合；禁止漂浮断笔、缺口、虚接，**禁止虚线 / 点线 / 虚线装饰框**。AI 很喜欢偷偷加虚线（S07 首版四周有一圈虚线花边、S11 首版的箭头是虚线），提示词里必须显式写 `ALL lines are solid, never dashed, never dotted`，负向词带 `dashed line, dotted line, dashed border`。批量出图时逐张检查这一条。
- **手**：不到必要时不画手——**全片只在 S01 出现手**，其余 26 镜只出现物件与线条。两条实测结论：① 白板马克笔风里，AI 画的手会带肤色渐变、指甲、肌肉结构，引入第 6 个色相并破掉 5 色约定，必须靠负向词 `realistic hand, skin tone, fingernails` 压住；② **只有当主体描述里本来就有人物/手时，才能在提示词里提"手"**。S27（流水线）主体里没有手，却因为套用了手部规则而把"手与马克笔"写进提示词，模型就在左下角硬贴了一只写实的手——这是 S27 首版翻车的原因。反过来 S01（两个人一张桌子）因为主体本来就有手，同样规则下出来的手是干净的黑线稿平涂。
- **人物**：只画极简线稿小人（背影/侧影/火柴人），**不画正脸五官**——手绘风 AI 生图最容易在脸和手上崩。已实测：**即使负向词写了 `no photorealistic people`，模型仍可能自己补一个带五官的小人**（S05 首版右侧就多画了一个闭眼微笑、还带腮红和手指的人物）。所以凡是该镜不需要人物的，正文里不要留任何"人"的暗示，负向词必须显式带 `person, people, facial features`。
- **禁止实心黑块**：模型会把"代码块 / 卡片 / 面板"涂成一大团实心黑（S19 首版右侧就是一块黑砖），这和"黑墨线稿"完全是两回事。凡涉及卡片类元素，主体里显式写 `outline only, no solid black fill`。

### 2. 统一提示词前缀（每条都要带）

> 与 `02-分镜与生图提示词.csv` 中每行"英文生图提示词"的前半段**逐字一致**，改动请两边同步。

```
hand-drawn whiteboard marker sketch illustration, single-panel explainer diagram,
off-white textured paper background, bold uneven black ink outlines, diagonal
hatching shading, palette limited to black plus cobalt blue and warm orange accents,
clean centered composition, generous negative space, 16:9,
no text no letters no words no numbers
```

（以下两版是同一串的等义写法，选你模型更吃的那个，但**全片只能用一版**）

- 带色值的版本：把 `off-white textured paper background` 换成 `off-white textured paper background #F7F5F0`，把 `cobalt blue and warm orange accents` 换成 `cobalt blue #2F6BFF and warm orange #FF7A45 accents`
- 强调明暗的版本：把 `diagonal hatching shading` 换成 `cel-shading with diagonal hatching`

### 3. 统一负向词

```
text, letters, words, chinese characters, numbers, watermark, logo,
photorealistic, 3D render, glossy, neon glow, gradient mesh, cluttered,
busy background, deformed hands, distorted faces, extra fingers, blurry,
low contrast, jpeg artifacts
```

### 4. 为什么画面里不要有字

手绘风下 AI 生成中文几乎必然糊成"鬼画符"，而且会污染风格一致性。所以本套方案的约定是：

- **画面 = 只画形状、物件、箭头、结构**
- **文字 = 100% 后期叠加**（字幕来自 `03-字幕.srt`，板书大字来自 `02` 的"屏幕板书文字"列）

这样既保证画面干净，也保证排版可控（字体、位置、出现节奏都能精修）。

## 四、先生图：三步走

**第 0 步｜已确认的出图链路（本项目内）**

`arkcli` 当前不可用（两个 profile 的 SSO 身份过期，Agent Plan 还卡在数据协议签署校验），因此走**项目自带的图片链路**：

```bash
cd backend
npx tsx scripts/gen-image.ts --prompt-file <提示词文件> --out <输出路径> --size 1920x1080
# 默认 configId=8（控制台按量 / doubao-seedream-5-0-flash-260915）
# 注意：默认 active 配置是 id=1 的 Agent Plan，其密钥当前 401，必须显式指定 configId=8
```

- 产物先落到 `data/static/images/<uuid>.jpeg`，脚本会再复制一份到 `--out` 指定位置。
- 实测：请求 1920×1080，模型超采样输出 **2816×1584**（同为 16:9），无水印。
- 该脚本不传业务实体 ID，因此**不会回写任何业务表**，只新增 `sys_task` 记录。

**第 1 步｜出一张风格锚点图（最重要）**
真正生图前，先用 S00 那一行（风格锚点）生成 1 张图，只调这一张，直到线宽、色板、纸纹、**线条连续性**都对。它决定后面 27 张的一致性。

本片锚点试了三版，**已定档 v3**：

| 版本 | 文件 | 结论 |
|---|---|---|
| v1 | `images/S00-style-anchor-v1.jpeg` | 墨线关系与留白好，但笔尖处**断笔**、旁边有漂浮笔画 → 弃用 |
| v2 | `images/S00-style-anchor-v2.jpeg` | 断笔修好（笔尖连出连续曲线），但**手更写实**（肤色/指甲）、黑色墨线感丢失 → 仅作连续性参考 |
| **v3** | `images/S00-style-anchor-v3.jpeg` | **定档**：无手、黑墨线为主、蓝橙仅点缀、线条全部连续闭合、留白充足 |

`02-分镜与生图提示词.csv` 已按 v3 的结论重写：全部 27 镜提示词都带"线条连续闭合 + 黑墨线为主"约束；只有 **S01 / S27** 保留手与马克笔，并强制为黑线稿平涂。CSV 由 `build-shotlist.py` 生成，改提示词请改脚本后重跑，不要直接手改 CSV。

**第 2 步｜锁定参数再批量出图**

- 分辨率：1920×1080（16:9）；若模型只出方图，用图生图/扩图补成 16:9，**不要用裁剪**（会切掉构图留白）。
- Seed：固定一个 seed；若模型支持，把风格锚点图作为 **style reference / 参考图** 一起传入。
- 每镜建议 **2–3 张候选**，按"线稿是否干净、色板是否跑偏、主体是否居中"三条筛。
- 一致性复查：把 27 张拼成一张 9 宫格/联系表（contact sheet）扫一眼，色偏和线宽不统一的挑出来重出。

**第 3 步｜补图与兜底**

- 崩图概率最高的三类：人物面部、手、成组的小图标。遇到就整张重出，别修。
- 生不出来的结构图（如 S11 的投影法），允许退化为"半示意图"：用几何方块 + 箭头表达，比强行写实更好。

> 若你想换成竖屏或 3D 等距风，只需替换 `02` 前缀与负向词；**分镜结构、屏幕文字、口播、字幕全都不用改**。

## 五、再合成：剪辑与音频

**动效建议（让静态图"活"起来）**

- 每镜 5–6 秒，用**缓入缓出**的轻微推近（100%→106%）或平移，避免生硬。
- 手绘风的天然转场是"擦除/划线揭示"：用遮罩从左到右揭开下一张图，比任何花哨转场都贴。
- 箭头、连线、圈注用后期画的**描边生长动画**补，别指望生图带箭头。

**音频**

- 口播：直接读 `01` 的正文。TTS 参数建议——语速 1.0x、句间停顿 0.15–0.25s、章节切换处停顿 0.5s。
- 若真人配音：`01` 里标了重音词和停顿位，照着念即可。
- BGM：轻快、无强节拍器感的中低音量电子/拨弦，音轨压到人声之下 −18 dB 左右。
- 无口播版：只留字幕 + BGM，适合做二次分发的静音版。

**导出**

- 主片：H.264 / 1080p / 8–12 Mbps / 30fps；音频 AAC 192 kbps。
- 封面：从 S27 或 S04 出一张 16:9 静帧，后期加封面大字（封面文案见 `04`）。

## 八、口径与免责

- 本片为**中立科普**：不出现任何设计工具、插件、厂商名称与对比结论。
- 涉及"效率提升幅度""成本"等量级判断时，全片只用**方向性表述**（如"大约要一到两个人年"），不编造具体百分比——出处见 `05`。
- 涉及技术实现的部分，采用业内较为一致的说法（设计稿本质是节点树 → 中间表示 DSL → 打印为各端代码），不同工具的细节实现各有差异，片中已用"通常""一般"等词限定。
