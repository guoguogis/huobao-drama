## 二、来源清单

1. **墨刀《什么是D2C设计模式？一文搞懂设计转代码》**（本次任务指定原文，2026-09-12 更新）
   https://modao.cc/ad/blog/what-is-D2-design.html
   → 提供：D2C 定义、四条核心优势、工具能力描述、三步实践流程。本片第一、三章主要依据。

2. **腾讯云开发者社区《D2C 设计稿转代码是怎么实现的？自己做一个可行吗？》**（神说要有光zxg，2022-11）
   https://cloud.tencent.cn/developer/article/2159914
   → 提供：节点树 → DSL → 各端代码的实现原理；绝对定位转 Flex 的投影法；分组、语义化 className、组件标注三类难题；图片输入需 AI 提取；"下限靠编辑器、上限靠 AI"；自研成本量级。本片第二章主要依据。

3. **腾讯云开发者社区《Figma 转代码，为什么总是差最后一公里？》**（梯度不陡，2026-06）
   https://cloud.tencent.com.cn/developer/article/2700070
   → 提供：最后一公里的定义（设计结构 → 工程语义）；D2C 的四条技术路线；metadata 的价值与陷阱；设计稿角色的变化；D2C 是研发系统问题而非插件问题。本片第四、五章主要依据。

4. **论文 Figma2Code: Automating Multimodal Design to Code in the Wild**（ICLR 2026，华中科技大学/浙江大学/马里兰大学等）
   https://arxiv.org/abs/2604.13648
   代码：https://github.com/CGCL-codes/naturalcc/tree/main/examples/figma2code
   → 提供：多模态输入（metadata + assets + screenshot）对还原度的提升；metadata 方法更易产生 rigid layout 与 arbitrary style tokens 的实验结论。第 3 条来源对它的转述已足够支撑片中表述，如需更严谨可直接引论文。

5. **Figma Blog《Design Context, Everywhere You Build》**
   https://www.figma.com/blog/design-context-everywhere-you-build/

## 三、口径与风险提示

**已刻意规避的表述**

- ❌ "效率提升 50%""开发成本降低 80%"之类的具体百分比 —— 未找到可核验的一手数据，片中一律改为方向性表述。
- ❌ "一键上线""完全自动化" —— 与来源结论相反，片中明确反对。
- ❌ 任何厂商/产品对比结论 —— 违背本片中立口径。

**需要留意的时效性**

- 第 2 条来源发表于 2022 年，其工具生态描述已过时（片中未引用具体工具，只引用原理部分，原理仍然成立）。
- 第 3、4 条来源为 2026 年，反映的是当下前沿状态；"Agent 进入真实代码库"仍属方向性判断，非既成事实，片中已用"开始""正在"限定。
- 设计令牌的标准仍在推进中（当前为社区组草案/技术报告阶段），片中未做标准化程度断言。

**若要做更严谨的版本，建议补三件事**

1. 引一次 Figma2Code 论文原文的量化结论（视觉还原 vs 响应式/可维护性的权衡）。
2. 补一个真实的、可公开引用的团队落地数据（需自行征得授权）。
3. 把"1–2 人年"的估算换成有署名的公开说法，或改为"业内常见的量级判断"。
