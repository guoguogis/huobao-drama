## 五、置顶评论（互动引导）

```
你最近一次听到"跟设计稿不太像"，是什么时候？
说这话的人是谁——产品、测试、还是你自己 review 的时候？

补一个视频里没细说的判断标准，给想上 D2C 的同学：
别看它第一版生成得像不像，看你第二天敢不敢在上面接着写业务逻辑。

你们团队的实际情况是哪一种？
A. 设计稿仍然是每个需求的必经环节
B. 已经有一部分需求直接跳过设计稿了
C. 试过 D2C，但生成的代码最后被重写了

评论区聊聊你的场景，我按类型再拆一期。
```

备选置顶（偏技术向）：

```
关于原理那段，补两个关键词方便你继续查：
1）中间表示（IR / DSL）：设计稿的结构必须先被"翻译"成一种中立的中间结构，
   才能打印成 Vue、React、小程序等不同目标；
2）设计令牌（Design Tokens）：颜色、间距、字号这些设计决策，
   只有被 token 化之后，才可能被工程系统稳定复用，而不是硬编码。

这两个东西在不在，基本决定了生成的是"一次性代码"还是"能维护的代码"。
```
