| Zed / OpenCode / Kimi | 多 agent 并行 + ACP；child session；`/swarm` + Tower | DeltaDB/CRDT；进程级多会话 |

### 2.2 并行多 agent / git worktree / 云端沙箱：2026 年的新分档线

**区分工具档次的不再是「模型多强」，而是「能不能并行跑、能不能关掉电脑继续跑」。** 三条已验证能力轴：

1. **git worktree 隔离**：Claude Code 有官方 worktree 文档（`--worktree`→`.claude/worktrees/`）[来源](https://code.claude.com/docs/en/worktrees.md)；**Qoder 最完整**（`--worktree` + Subagent `isolation: worktree`）[来源](https://docs.qoder.com/cli/parallel-tasks.md)；Cursor 3.2 Agents Window 内置 worktrees [来源](https://cursor.com/changelog/04-24-26)；Gemini CLI 有实验性 `--worktree`（**退出不自动清理**）[来源](https://geminicli.com/docs/cli/git-worktrees.md)；GitHub Copilot app **每会话独立 worktree 且数量不限**；Factory **默认上限 15 个**；Kilo Code 的 Orchestrator 跨并发 worktree 委派；CodeBuddy CLI 文档列有 Git Worktree 支持（细节未核实）。**Amp 的 Orbs 刻意不用 worktree**，其自有机器 Runner 2026-09-22 起才支持。
2. **云端沙箱 / 关掉电脑继续跑**：Cursor Projects「跑在云端自己的机器上，关掉笔记本不会停」[来源](https://cursor.com/changelog/projects)；Devin **每 session 独立隔离 VM**，Outposts 下 N worker = N 并发 [来源](https://docs.devin.ai/cloud/outposts/quickstart.md)；**Qoder CN 官方原文「关闭客户端后任务继续运行」**[来源](https://docs.qoder.cn/product-overview/introduction-of-qodercn)；Jules **每任务一台独立 Google Cloud VM**；Kiro CLI 有 V3 cloud sessions；Factory 的 Droid Computers 空闲自动暂停、新会话自动唤醒；Trae 两版以「云端任务并发数」分档（2–20）。
3. **规模化 subagent 编排**：Cursor Projects 协调器「不自己写代码」，官方称可派发**上千个 subagent** [来源](https://cursor.com/changelog/projects)；2026-08-19 起 subagent 可各跑自己的 VM [来源](https://cursor.com/changelog/08-19-26)；Claude Code subagent 默认并发 20 [来源](https://code.claude.com/docs/en/sub-agents.md)。

> **⚠️ 反面证据（重要，别被营销数字带偏）**：并行不等于更快。OpenAI Codex 开发者体验负责人 2026-09-15 公开表示一次跑超过**两个** sub-agent「几乎肯定是纯烧 token 且零质量收益」，称之为「**coordination tax**」；Nous Research 一次重构跑了 **1,393 个 subagent、峰值 218 并发、约 $19,300**。[来源](https://mixed-news.com/en/codex-developer-parallel-agents-limit-nous-1393-agents/) 更硬的约束来自 GitHub：Copilot cloud agent **单 session 59 分钟硬上限、单分支、单 PR**。[来源](https://raw.githubusercontent.com/github/docs/main/content/copilot/concepts/agents/cloud-agent/about-cloud-agent.md) Anthropic 则给出 **agent teams 约消耗标准会话 7 倍 token**。[来源](https://code.claude.com/docs/en/costs.md)

## 3. 关键结论

1. **协议层已不再是竞争点，而是公共基础设施。** MCP + A2A + AGENTS.md + SKILL.md 全部收归 AAIF 中立治理。[来源](https://aaif.io/blog/a2a-joins-aaif) 工具选型的可迁移性显著上升。**但要注意规范与实现的落差**：Skills over MCP 已 Final，主流客户端却基本未实现。[来源](https://modelcontextprotocol.io/extensions/client-matrix)
2. **竞争焦点上移到「编排与算力」，而算力正在被垂直整合。** SpaceX 收购 Cursor、Cursor 与 SpaceXAI 共训 Grok、Anthropic 向 SpaceXAI 采购算力，都是同一逻辑。[来源](https://cursor.com/blog/joining-spacex)
3. **模型供应关系已政治化断裂。** OpenAI 因「无法确信 SpaceX 会按 OpenAI 条款使用技术」而终止向 Cursor 供模型（2026-11-12 生效）。[来源](https://gigazine.net/gsc_news/en/20260829-openai-decided-to-end-partnership-with-cursor) **多模型冗余从「优化项」变成「风险控制项」。**
4. **计费普遍转向按量，「按席位预算」的时代结束了。** Copilot 改 AI Credits 且**额度组织池化**——一个人的重度使用会消耗同事的额度，这把 AI 治理从 IT 问题变成团队内部资源分配问题。[来源](https://www.cloudzero.com/blog/github-copilot-enterprise-pricing/)
5. **并行 agent 存在明确的收益递减。** 官方人士称超 2 个 sub-agent 近乎纯烧钱、Nous 实测 1,393 个 subagent ≈ $19,300、Claude agent teams 约 7× token、GitHub cloud agent 59 分钟硬上限——**并发能力必须与任务可分解性匹配**。
6. **「已官宣」与「已交付」差距很大。** Agent HQ 在 2025-10 官宣「任意 agent」，到 2026-09 **只落地 Claude 与 Codex 且仍是 public preview**，Devin/Jules 未进支持列表。[来源](https://raw.githubusercontent.com/github/docs/main/content/copilot/concepts/agents/about-third-party-coding-agents.md) 采购必须以官方支持矩阵为准，而非发布会。
7. **产品存续期已短于典型采购周期。** 十二个月内：Gemini CLI 免费档死、Windsurf 品牌死、Roo Code 死、Void 死、iFlyCode 死、Aider 停摆、SWE-agent 被自家判 legacy、Continue 被收购、Cursor 易主、通义灵码与 Comate 改名。**「一次选型管两年」不再成立，必须按季度复核。**
8. **SWE-bench 分数已不能作为选型依据。** arXiv:2609.17394（2026-09-15）审计 254 份提交后指出，**29 组相邻 top-30 配对在 α=0.05 下 McNemar 检验无一能被区分**；within-model scaffold 区间可达 **29.8 个百分点**，而 top-30 总分差仅 8.8 点。[来源](https://arxiv.org/abs/2609.17394) 同时 OpenAI 已停止报告 Verified 成绩并在 2026-07-08 撤回对 SWE-bench Pro 的推荐。[来源](https://gigazine.net/gsc_news/en/20260709-openai-coding-evaluations)

**(2) 两起必须知道的安全/合规事件**

- **xAI `grok` CLI 目录上传事件**：Simon Willison 2026-07-15 逐行核查发现，在目录中运行 `grok` 会**把整个目录上传到 xAI 的 GCS bucket**，有用户报告丢失 SSH 私钥、密码库、照片。Musk 回应「所有此前上传到 SpaceXAI 的数据将被彻底删除」；**xAI 于 2026-07-12 关闭默认保留、2026-07-15 以 Apache 2.0 开源整个 Grok Build 代码库**（`xai-org/grok-build`，844,530 行 Rust，工具实现移植自 OpenAI Codex 与 OpenCode）。**注意**：官方 npm 包 `@xai-official/grok` 的 license 仍是 **Proprietary**——「xAI 开源了编码 agent」**只在 harness 层成立**。[来源](https://simonwillison.net/2026/Jul/15/grok-build/) **「Grok Code Fast 2」零证据，勿引用。**
- **Grok Bot 条款的合规约束（最硬的一条）**：Grok Bot Terms 第 4 条明确，同一用户的多个 Bot **共享持久环境且「must not be treated as separate security boundaries」**；**删除 Bot 可能不会删除**共享文件/会话/凭据/routines；2.4 条 Provider 对任何 Agentic Action 免责。[来源](https://cursor.com/terms/grok-bot)
