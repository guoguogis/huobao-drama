## 一、分层地图：2026 年 9 月的四层结构

AI 设计工具在 2026 年已经分化成四层，彼此的输出形态和「可编辑性」完全不同：

**第 1 层 · 设计画布内的 AI（AI-in-canvas）**
在既有矢量设计工具里加 AI 能力，产物是**可继续编辑的设计文件**。Figma 2026 年已把矩阵铺成 Figma Design / Make / Dev Mode / Weave / Motion / Sites / Buzz 多条产品线，其中 Weave（图像·视频·音频 AI 工作流）、Motion（生产级动效）为 2026 年新品 [来源](https://help.figma.com/hc/en-us/articles/33459875669015-How-AI-credits-work)（该帮助中心页面的产品导航，抓取于 2026-09-24）。国内这一层已明显收缩：**Motiff 妙多已关停**，实际玩家只剩 MasterGo 莫高、即时设计、Pixso 三家，它们的价值同样在于「生成物仍是可编辑设计稿」。

**第 2 层 · 对话式生成设计与原型（prompt-to-design）**
Anthropic Claude Design、Figma Make、Replit Design、Magic Patterns、Subframe、Onlook。产物是**可交互原型 / 前端代码**，不是位图。这一层在 2026 年发生的关键变化是：**从「一次性生成」转向「接入企业设计系统」**。

**第 3 层 · 全栈 vibe coding（prompt-to-app）**
v0 (Vercel)、Lovable、Bolt.new、Replit Agent。产物是**可部署的完整应用**（React/Next.js + 数据库 + 鉴权），设计只是入口。

**第 4 层 · 视觉资产生成（prompt-to-image）**
OpenAI GPT Image 2.5（榜首）、Google Nano Banana 2 / Nano Banana Pro、字节 Seedream 5.0（Pro）、Midjourney V8.x、Adobe Firefly、Ideogram、Recraft。产物是**位图**，本质上不可编辑（只能重生成或局部 inpaint）——**唯一例外是 Recraft，官方称其可输出可编辑的生产级 SVG** [来源](https://www.recraft.ai/docs/recraft-models/recraft-v4-1)。

这条分层的产业含义是：第 4 层的产物**无法**直接进入生产设计系统；第 1 层天然在内；第 2、3 层处在中间地带，取决于它是否读了你的 token 与组件库。

## 三、关键技术结论（含具体数字）

### 3.1 设计稿 → 代码：Figma 已把「双向」打通，但成熟度不均

- Figma 的 Dev Mode MCP Server 现已提供**远程服务器**（`https://mcp.figma.com/mcp`，OAuth 登录），官方支持 Claude Code、Codex、Cursor、VS Code、Xcode 27 beta [来源](https://developers.figma.com/docs/figma-mcp-server/remote-server-installation/)。时间线是：2025-06-04 Dev Mode MCP beta（仅桌面端）→ 2025-09 Schema 2025 上 GA 并发布 Code Connect UI GA → 远程 MCP 上线 → **2026 年 5 月起补齐 `write to canvas` 与 `code to canvas`** [来源](https://developers.figma.com/docs/figma-mcp-server/)。
- **配额是这条链路最现实的约束**（官方口径）：远程 MCP 对所有席位的所有方案开放，但对 **View/Collab 席位限 6 次/月**（Starter 20 次/月）；**Dev/Full 席位按方案分档——Professional 200 次/日（10 次/分）、Organization 200 次/日（15 次/分）、Enterprise 600 次/日（20 次/分）** [来源](https://developers.figma.com/docs/figma-mcp-server/rate-limits-access/)。Code Connect 需 **Org/Enterprise + Full/Dev 席位**，且**框架专用 parser 已停止维护**、Code Connect 文件**不被执行**（条件表达式原样输出、不能循环动态构造）[来源](https://developers.figma.com/docs/figma-mcp-server/code-connect-integration/)。
- 官方列出的 MCP 能力包括：**写入画布**（创建/修改 frame、component、variables、auto layout）、**从实时 UI 反向生成 Figma 设计稿**（code to canvas）、从选中 frame 生成代码、抽取设计上下文（变量/组件/布局）、读取 Make 资源、Code Connect 组件映射 [来源](https://developers.figma.com/docs/figma-mcp-server/remote-server-installation/)。
- 2026-03-24 Figma 宣布画布对 agent 开放：`use_figma` 工具让编码 agent **直接写入设计文件**；`generate_figma_design` 可把实时 HTML 转成可编辑 Figma 图层；同时发布 9 个社区 Skills（如 `/figma-generate-design`、`/apply-design-system`、`/sync-figma-token`）；**beta 期免费，之后转向按量计费** [来源](https://abduzeedo.com/node/89190)。
- 限制同样官方写在文档里：MCP 常「只返回 web/React 代码」、请求变量却拿到代码、大 frame 拖慢、图片加载失败、500 错误、rate limit 等，官方为每一类都设了 FAQ 条目 [来源](https://developers.figma.com/docs/figma-mcp-server/remote-server-installation/)。这说明**「设计稿→代码」在 2026 年仍是需要人写规则、写 Skill 才能稳定复现的工程，而不是开箱即用**。
- **还原度有可量化基准，但数字本身说明「远未收敛」**。DesignCoder（浙江大学 + 华为，Information and Software Technology 2026；arXiv 2506.13663）在 300 个真实 UI mockup（250 个来自 Figma 社区 + 50 个来自企业项目）上评测 React Native 代码生成：相比最强基线 Prototype2Code，视觉相似度 MSE 改善 **37.63%**、CLIP **9.52%**、SSIM **12.82%**；代码结构相似度 TreeBLEU **+30.19%**、Container Match **+29.31%**、Tree Edit Distance **+24.67%** [来源](https://ar5iv.labs.arxiv.org/html/2506.13663)。但其绝对水平仍难看齐人工：**TreeBLEU 仅 0.69**（即约三成子树结构不匹配），而 GPT-4o 直接生图生代码只有 **0.24** [来源](https://ar5iv.labs.arxiv.org/html/2506.13663)。论文同时用专业开发者做用户研究，代码可用性 4.52 vs 3.57、修改效率 4.20 vs 3.24、可维护性 4.32 vs 3.32（5 分制）[来源](https://ar5iv.labs.arxiv.org/html/2506.13663)。**这组数字的产业含义是：结构还原度决定了「生成的是原型还是能进仓库的代码」——0.24 的基线属于前者，0.69 也仍需人工收尾。**
- **「看起来像」已经基本解决，「细节忠实」和「功能正确」远未解决**。Design2Code（arXiv 2403.03163，484 个真实网页）上 GPT-4o 的 Block-Match 达 **93.0**、CLIP **90.4**，且 **49% 的生成页被认为可直接互换部署、64% 的案例里 AI 稿被评为比原稿设计更好** [来源](https://arxiv.org/abs/2403.03163)；但更严格的结构指标立刻塌陷——Waffle（arXiv 2410.18362）的 HTML-Match 仅 **37.00%**（GPT-4o 11.40%）[来源](https://arxiv.org/abs/2410.18362)，**WebGen-Bench（NeurIPS 2025 Datasets & Benchmarks，arXiv 2505.03733）最强组合也只有 27.8%** [来源](https://arxiv.org/abs/2505.03733)；*Pattern over Pixels*（arXiv 2608.03691）进一步发现生成器存在 **69.78%–80.22% 的重复模式偏置率**，文字扰动任务准确率仅 **7.89%** [来源](https://arxiv.org/abs/2608.03691)。产业侧的经验结论是：**仍需 20–40% 的人工收尾**（该数字为第三方实践口径，**未核实**）。
- **一个明确的评测空白**：目前所有 image-to-code 基准测的都是**渲染相似度或功能测试**，**没有任何一个在测「生成结果在 Figma 里是否可编辑、是否绑定变量、是否复用组件」**——而这恰恰是「设计稿 → 代码」链路最核心的工程指标 [来源](https://developers.figma.com/docs/figma-mcp-server/code-connect-integration/)。评估工具选型时不能只看榜单分数。

### 3.2 可编辑矢量 vs 生成位图：这是采购决策的分水岭

- Claude Design 的导出目标是 Canva、PDF、PPTX、独立 HTML、Claude Code（2026-04 官方公告 [来源](https://www.anthropic.com/news/claude-design-anthropic-labs)）；2026-06 更新后新增 Adobe、Base44、Canva、Gamma、Lovable、Miro、Replit、Vercel、Wix 等目的地，**但官方列表中没有 Figma** [来源](https://www.aiposthub.com/claude-design-new-features-design-system-code-sync/)（2026-09-13）。要把 Claude Design 产物变回 Figma 可编辑图层，社区走的是第三方插件路线，例如 Figma 社区插件「Claude Design to Figma」[来源](https://www.figma.com/community/plugin/1674169407347533342/claude-design-to-figma-import-decks-slides-as-editable-layers)。
- 反向链路（代码 → 可编辑设计稿）已产品化：Figma `generate_figma_design` 与 Replit Design 的「Import from URL / Figma / Claude」并存 [来源](https://abduzeedo.com/node/89190)、[来源](https://docs.replit.com/design/what-is-replit-design)。

### 3.4 评测基准：Design Arena 已成事实标准，但结果是「模型榜」而非「工具榜」

- Design Arena（Arcada Labs，YC 项目）自称「最大的众包 AI 设计基准」，覆盖网站、UI 组件、图像、Logo、SVG、幻灯片、游戏、3D、数据可视化等 30+ 榜单 [来源](https://www.designarena.ai/)；上线 4 周吸引 136 个国家 4.7 万用户，累计 190+ 国家使用 [来源](https://www.ycombinator.com/launches/O5h-design-arena-1-benchmark-for-ai-design)。
- **方法论**：4 个模型 5 场对战锦标赛（每场 1 票）+ **匿名人类投票** + **Bradley-Terry** 打分（`Rating = 400×log₁₀(strength)`，阈值 0.0001、200 次迭代），榜单每 2 小时刷新；票数 <50 标 "new"、约 200 票前标 preliminary [来源](https://www.designarena.ai/)（方法细节经第三方快照核对，**官方方法页未直接抓取**）。
- 2026-09-02 快照的**分项榜首**：Website = **Kimi K3 1362**（共 173 个模型）、UI Component = **Claude Fable 5.1 1381**、Image to HTML = **Kimi K3 1259**、Graphic Design = **GPT Image 2 1451** [来源](https://benchmarklist.com/arenas/design_arena_website/)。**注意：官方 Changelog 显示 9-20 至 9-23 仍在新增模型（含 claude-opus-5-5），因此 9-24 的真实名次已与 9-02 快照不同** [来源](https://www.designarena.ai/)。
- 2026-09-21 数据版本的 **Code Categories 榜**：Kimi K3 **1385**（6,718 票，开源权重）、Muse Spark 1.3 Max **1369**、GPT-6 Astra (xhigh) **1365**；共 166 个模型 [来源](https://www.datalearner.com/en/leaderboards/external/arcada-code)。
- **WebDev Arena 的榜首在 9 月内至少换过一次**：9-02 为 claude-fable-5.1-max **1765.37**（第二名 qwen3.8-max-0902 1687.74），9-05 换成 gpt-6-astra-max **1797**（但仅 1,199 票），Fable 5.1-max 退到 1762（2,275 票）[来源](https://benchmarklist.com/arenas/)（官方 `arena.ai` 与 `lmarena.ai` 在本次抓取中分别返回 403 / fetch failed）。**因此「9-24 Claude Opus 5.5 以 1818 分登顶」这一说法只有单一低可信度商业站点来源，属于未核实** [来源](https://www.lumevalley.com/article-10150.html)；同一来源给出的 Artificial Analysis Coding Agent Index 单任务成本 **$13.04** 同样未经官方核实。
- **PosterReward**（arXiv 2603.29855，2026-02-23 提交，Comments 明写 Accepted by CVPR'26；HKUST(GZ) + 美团 + HKUST）：指出既有 reward model 只看全局美感、忽略排版与字体，构建 **Poster-Preference-70K**（7 万条海报偏好），提出五维评价体系（基础视觉质量、AI 伪影、文字准确性、提示词一致性、美学价值），并用四阶段级联训练（SFT → 拒绝采样 → Scoring Module → GRPO）。**头条数字：PosterReward 在 PosterRewardBench-Basic 达 86.7%、Advanced 达 86.0%，而 HPSv3 分别只有 72.9% / 41.2%（Advanced 上差 44.8 个百分点）；成对模型 PosterReward-Pairwise 在 Basic 上 83.0%，仅次于 GPT-5 的 85.4%，且位置偏置最小** [来源](https://ar5iv.labs.arxiv.org/html/2603.29855)、[来源](https://arxiv.org/abs/2603.29855)。
- **榜单不能说明什么**：① 榜单≠工程质量——WebDev Arena 的投票只针对「单次请求后渲染出来的观感」，不含可维护性、也不含在你既有项目里的行为；② arena 分数不可复现（模型池、命名、采样参数都在变）；③ **Elo 不可跨 arena 比较**（同一模型在 Design Arena 内部不同分类的分数就有 1335–1392 的差异）；④ 学术基准的分数不可横向相加，因为数据集与任务定义不同。
- 读法：这些榜单衡量的是**底层模型**（Kimi K3、GPT-6 Astra、Claude Fable 5.1），不是工具本身。同一模型在 Figma Make、Claude Design、v0 里的表现差异，主要来自上下文工程与设计系统接入质量，榜单给不出答案。**引用这些数字时必须带快照日期。**

## 五、「一次性 HTML/图片」与「进入生产设计系统」的本质差异

| 维度 | 一次性产物 | 可进生产设计系统 |
|---|---|---|
| 形态 | 位图 / 单文件 HTML / 独立新应用 | 设计文件图层、组件、token |
| 品牌一致性 | 靠 prompt 描述，逐次漂移 | 由设计系统强制，自动套用 |
| 迭代成本 | 每次改动重新生成 | 改组件，全局生效 |
| 交给工程 | 截图或新仓库 | Code Connect / MCP / CLI 同步到既有仓库 |
| 可审计 | 无 | SSO、RBAC、审计日志、数据驻留 |

判断一个工具属于哪一边，只看三件事：**① 它是否读取你的 token 与组件库；② 产物是位图还是矢量/组件；③ 它写进你的仓库还是另起一个沙箱。**
Figma Make 属于「读了你的 Make Kit，但生成的是沙箱里的新应用」[来源](https://www.builder.io/compare/builder-vs-figma-make)；Subframe 属于「代码即源、CLI 同步到你的仓库」[来源](https://docs.subframe.com/learn/introduction)；Onlook 属于「直接编辑你仓库里的 React 代码」[来源](https://www.onlook.com/pricing)；图像模型一律属于左边。

zeroheight 2026 年对 123 位设计系统从业者的调研给了这组张力一个量化画像：**82% 的团队已在用 AI，61% 表示使用量显著上升，但「设计生成」是满意度最低的环节（净满意度 −53），63% 最满意的是「写文档」；59% 反映有 UI 绕过了设计系统，50% 认为「影子 AI」已造成实际问题** [来源](https://zeroheight.com/resources/state-of-ai-in-design-systems/)。

### 企业采用的判断标准（建议清单）

1. **先问产物形态**：需要交付矢量设计稿 → 第 1 层；需要可运行前端 → 第 2/3 层；只需要营销素材 → 第 4 层。混用会导致返工。
2. **先修设计系统，再上 AI**：agent 读取组件命名与 token 结构的质量直接决定输出质量 [来源](https://abduzeedo.com/node/89190)。zeroheight 的结论是「文档优先、MCP 其次、质量优于覆盖率」[来源](https://zeroheight.com/resources/state-of-ai-in-design-systems/)。
3. **预算按「可接受率」而非「生成次数」算**：$0.134/张的图若 5 张里只有 4 张可用，实际成本约 $0.17/张 [来源](https://www.modellix.ai/blog/nano-banana-pro-pricing/)；Claude Design 的 30 分钟打满周额度则意味着必须按人分配额度上限 [来源](https://www.uniflow.kr/en/claude-design-ai-credit-comparison-chatgpt-gemini-grok/)。
4. **确认训练数据条款**：默认开启训练 vs 默认关闭，在 Starter/Professional 与 Organization/Enterprise 之间是相反的 [来源](https://www.builder.io/compare/builder-vs-figma-make)。
5. **确认治理能力**：Claude Design 在 Enterprise 默认关闭、需管理员启用，且**尚无审计日志** [来源](https://www.aiposthub.com/claude-design-new-features-design-system-code-sync/)；Figma Organization 及以上才有审计日志与数据驻留 [来源](https://www.builder.io/compare/builder-vs-figma-make)。
6. **要求「回得来」**：如果工具产物不能回到你的设计系统（例如 Claude Design 无原生 Figma 导出），它就只能停在探索阶段。

## 六、2026Q4–2027 趋势判断

1. **「生成」不再是卖点，「接入设计系统」才是。** 2026 年 4–6 月，Claude Design 从「对话出图」升级为「导入 GitHub/设计文件建设计系统 + 画布编辑 + 同步 Claude Code」[来源](https://www.aiposthub.com/claude-design-new-features-design-system-code-sync/)；Figma 在 4 月发布 Make Kits [来源](https://www.builder.io/compare/builder-vs-figma-make)；Replit Design 内置设计系统与 Mobbin [来源](https://replit.com/blog/introducing-replit-design)。**Q4 的竞争焦点会是「谁的 agent 更懂你的组件库」，而不是谁的 demo 更惊艳。**
2. **模型能力正在被商品化，工具价值向上层转移。** Design Arena Website 榜前 3 名分差只有 24 分 [来源](https://benchmarklist.com/arenas/design_arena_website/)，且中国开源模型 Kimi K3 登顶 [来源](https://www.datalearner.com/en/leaderboards/external/arcada-code)。当底层模型差距收窄，工具层的护城河只剩上下文工程、设计系统接入和合规。
3. **「设计→代码→设计」闭环会出现，但 2027 年前仍需人写规则。** Figma 已有 `use_figma`（写画布）、`generate_figma_design`（HTML→图层）、Code Connect（组件映射），beta 期免费、之后按量计费 [来源](https://abduzeedo.com/node/89190)。**按量计费意味着「同步」本身将成为一项持续成本**，这是企业预算里目前普遍缺失的一行。
4. **额度经济学将取代座位经济学。** Figma 用 credit 制并把 Make 锁定 Full seat [来源](https://help.figma.com/hc/en-us/articles/33459875669015-How-AI-credits-work)、Claude Design 与 Chat/Code 共用额度池 [来源](https://www.aiposthub.com/claude-design-new-features-design-system-code-sync/)、Replit 引入 Economy/Power/Turbo 三档（Turbo 请求成本最高 6×）[来源](https://replit.com/blog/pro-plan)。**采购谈判的关键指标会从「每座位多少钱」变成「每个可用产出多少钱」。**
5. **位图层的「可编辑化」是被低估的下一战场。** Seedream 5.0 已支持笔刷式精准选择与调整元素 [来源](https://www.ithome.com/0/920/755.htm)，Recraft 走 SVG 路线 [来源](https://www.recraft.ai/docs/recraft-models/recraft-V4)。谁先把「生成位图」变成「生成带图层的可编辑资产」，谁就打通了第 4 层与第 1 层。
6. **风险提示**：Anthropic 发布 Claude Design 当日 Figma 股价一度下跌约 7%、Adobe 跌 1.5% [来源](https://me.mashable.com/tech/70088/what-is-anthropic-claude-design-tool-launched-to-rival-figma)（2026-04-20 报道）；但 5 个月后的今天，Figma 反而把 agent 接进了自己的画布——**这一轮的赢家不一定是模型公司，而是控制设计系统与代码仓库的那一层。**
